Tray

RapidCap minimises to tray, so for most of its life this small square is the product. The icon is built — tray::rgba rasterises the ring for five states, and PlatformRuntime::set_state pushes a fresh icon and tooltip on every transition. The menu is built too — tray_menu rebuilds it on every state change, so its items follow the capture the same way the icon does. The one thing the code does not draw is the header: a native menu item is a single line, so it reads RapidCap — Recording video where the mock stacks the name over the state.

The tray icon is the only UI during a recording — the panel is minimised and the HUD is a 36px pill on another part of the screen. That is why the icon shipped before the menu did: without it, a running capture and an idle app look identical unless the user goes hunting for the HUD.
The menu is native and will stay native. It is a tray_icon::menu::Menu, so Windows draws it — nothing on the Menus page applies here, and the mocks above are only saying which items to add and in which order. Accelerator text on a native item is a label, not a binding: muda does build an accelerator table alongside the item, but nothing in RapidCap runs TranslateAccelerator over it — the hotkeys are global and fire whether or not the menu is open.
