Errors & feedback

Three states the product has in code and had nothing in design: CaptureState::Error, a successful save, and the panel while the overlay is open.

Error — replaces the footer

Recording failed — disk full
The whole footer becomes the error. Chips are gone — nothing else matters until this is read.
Screen capture unavailable — another app is using the display
Not everything can be retried. Retry appears only when the failed command is idempotent.
Encoding failed — see details
Long technical strings are summarised; the raw error lives in the tooltip and behind Copy log.
Amber, not red. Red already means "capture is running" in this product — a red error bar under a red recording frame is unreadable. --warn #E8A33D is the only new colour in the system, and it exists solely so failure never gets confused with recording.
Built. The error survives until dismissed or until the next capture succeeds, and CaptureState::Error now carries a CaptureFailure { summary, detail }. The summary is written where the failure happens — finish_recording knows the operation is "Recording", finish_screenshot knows it is "Screenshot" — and the raw detail rides along untouched, into the hover text and the screen-reader label. Nothing is truncated: a summary that would not fit reads see details instead of thirty-nine characters of an FFmpeg line. Retry re-runs the command the failure came from, and Copy log puts the raw detail on the clipboard as plain text.
Two departures. The summary caps at 40 characters, because the same string also goes to the status well, which sizes to its content in a 400px row that already holds two chips. So the middle bar above really reads Screenshot failed — see details: its 60-character wording would need the code to classify error text by substring, and a heuristic that mislabels a failure is worse than one that points at the detail. For the same reason Retry appears whenever the failure came from a command that starts a capture, rather than only when that command is idempotent: idempotence is a property of the error, so deciding it would mean the same guessing from message text. Pressing Retry on something that fails again costs a click; guessing wrong costs a wrong button. Copy log does follow the spec — it appears only when the bar is summarising, because a bar already showing the whole error has nothing left to copy.

Saved — a chip that expires

Copied
A screenshot saved. The chip is pressable — it opens the file. It replaces the folder chip for 6s, then fades back.
00:42 · 12.4 MB
A recording saved. Duration and file size land in the status well — the two things you check before sending a clip.
The confirmation is a control, not a toast. A toast that floats over the desktop is one more thing to dismiss; a chip in the footer is already where the user's eye is, is clickable, and expires on its own. Saving is the moment the product earns trust, and it used to pass in silence.
The label is trimmed from the middle. File names carry a timestamp, and a whole one does not fit 152px of chip. The chip is overflow_hidden, so an untrimmed name would be cut mid-character and lose its extension — the one part that says what was captured. saved_label keeps the process name at the front and the extension and collision guard at the back, and the tooltip still carries the whole path.
Both halves ship. MainWindow subscribes to CaptureEvent::OutputSaved, holds the capture for SAVED_CHIP — 6s — and gives the slot back to the folder chip when the timer fires or the chip is pressed. It takes that slot rather than adding one, so the footer never reflows under the pointer, and a second save inside the six seconds hands the chip straight on instead of letting the first timer clear it. The well belongs to the chip for those six seconds, because the controller is already back to Idle and would otherwise read "Ready" over the top of a confirmation that just appeared. Only the fade is missing: the chip pops in and out.
The event carries what the well needs. OutputSaved takes a SavedOutput now: the path, the recorded length — None for a screenshot, which is what tells the two apart — and whether the clipboard write succeeded. The size is a metadata call made once when the event lands, not on every frame. A clipboard failure does not fail the capture, so it travels as a flag rather than as an error, and it is what turns the screenshot well into Copied or leaves it at Saved.

Selecting · Esc to cancel
Built. While the overlay is open the panel steps back: every card drops to 45% except the armed one, chips hide, and the status well carries the escape route. The armed card is the one whose kind is being selected, not the one holding the target — a region capture starts with no target at all. The chips leave rather than fade: a chip at 45% is still a tab stop, and there is nothing behind it worth tabbing to while the overlay owns the pointer. The scrim now covers every display, so the panel is always behind it — but the scrim is translucent, and a panel that reads as armed rather than frozen is what the user sees through it in the moment before they drag.
