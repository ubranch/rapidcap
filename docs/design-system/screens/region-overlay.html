Region overlay

A transparent popup sized to the display under the cursor. One surface serves both capture modes — drag for a region, click for a window. Esc cancels and closes.

Dragging a region

1280 × 720
Click window or drag region · Esc cancel
The rect grows from the anchor toward the live cursor in any direction. The badge reports physical pixels — logical size × scale_factor, so a 150% display reads the real output size.

Hovering a window

chrome.exe
Click window · Esc cancel
Hover snaps to the real window bounds under the cursor and labels it by process name. Same 2px accent border, accent tint instead of the neutral drag fill.

Multi-monitor

Every display dims. Only the one under the cursor takes input — the others are a scrim and nothing else, so a stray click on the second monitor cancels rather than captures the wrong thing.

Code delta: open_region_overlay calls monitor_under_cursor() and opens one window on that display. Today the other monitors stay bright and fully live — the desktop looks normal while the app is modal, which is the worst of both. This spec needs a scrim window per display, with only the active one handling mouse events.
Overlay chrome uses the panel's own tones — badge and hint are rgba(28,28,28,.92), which is --bg-card at 92%. Accent, not white, marks the selection: white edges disappear over bright content, and the product already spends its one colour on selection state.
