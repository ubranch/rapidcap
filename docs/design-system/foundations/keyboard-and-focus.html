Keyboard & focus

RapidCap is a hotkey tool that happens to have a window. Everything reachable by mouse is reachable by keyboard, and the five things people actually do are reachable without opening the window at all.

These are not settings. They are a fixed array — hotkey_specs() in platform/mod.rs, five entries, one per CaptureCommand. The hotkeys field on Settings is marked Retired: an old config that still carries it loads fine, and saving never writes it back. Every shortcut pill on a mode card is derived from that same array, so the panel cannot advertise a key the app never registered. RapidCap --probe prints the live list.
Alt+Q and Alt+E are shared with ShareX. They ship regardless, because those two were asked for by key rather than by role. RegisterHotKey is first-come-first-served, so on a machine already running ShareX one of them loses the race and does nothing at all. PlatformRuntime collects every chord it could not register and hands the list to the panel, which turns that card’s pill amber and prints Alt+E · taken — the word rides along because a colour is not a word. The dead chord also drops out of the card’s aria-keyshortcuts, so a screen reader stops offering a key that does nothing. The other three are primary + Shift + a mnemonic letter and are unclaimed by either OS, "primary" being Ctrl on Windows and Command on macOS.

Alt+F4Exits, same as the close button — but not during a capture, where it minimises to tray instead. Minimise is the tray route at any time.

Escape always goes somewhere

  • Menu open → close it, focus back on the chip that opened it.
  • Overlay open → cancel selection, state returns to Idle, panel restores.
  • Countdown running → cancel the capture before it starts.
  • Recording → nothing. Esc must never destroy a recording in progress; Stop is deliberate or it is not a stop.
  • Settings or Gallery → back to the panel.
  • Error showing → dismiss the error, keep the panel.
  • Panel idle → minimise to tray.

Built. All nine stops are reachable. Tab and Shift+Tab run through focus_next and focus_prev; the titlebar buttons are focusable and answer Enter and Space through their own key contexts, so Enter on Close is never Enter on Minimize beside it; every control has a stable accessibility_id; the status line carries role=Status and no focus.
The segmented control is one stop. The track owns it — role=RadioGroup, tab_stop, and the RapidCapCountdown key context that Left and Right are bound to. The three slots are role=RadioButton and are not focusable at all; they carry aria_position_in_set and aria_size_of_set, which is what makes the announcement read "3 of 3". Arrows wrap. A settings file hand-edited to a delay that is not on the track lights no slot, and the first arrow press puts it back on at whichever end it was pressed towards.
Home and End go through nothing. GPUI has focus_next and focus_prev but no focus_first; stepping forward from nothing focused lands on the first tab stop and stepping back from nothing lands on the last, so both actions blur and then step once.
Escape during a recording does not hide the panel either. "Nothing" in the table above means nothing: minimising to the tray while a capture runs would leave the HUD as the only way back, which is a route out of a recording that the user did not ask for. escape in window.rs walks the ladder in order — error first, then a run-up, then the recording states, then the tray.
Still missing: the focus-visible spacer on filled controls, and the whole Menu column of the table above. menu.rs does not exist yet, so there is no menu to close, no item to arrow between, and no trigger to return focus to.
