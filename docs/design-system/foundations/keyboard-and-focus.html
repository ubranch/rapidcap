Keyboard & focus

RapidCap is a hotkey tool that happens to have a window. Everything reachable by mouse is reachable by keyboard, and the four things people actually do are reachable without opening the window at all.

Record GIF · stopCtrl + Shift + PrtSchotkeys.gif
The GIF default collides. Ctrl+Shift+PrtSc belongs to Windows Snipping Tool, so registration loses and the key does nothing — silently, because global-hotkey failures are not surfaced. Either rebind the default to Alt+G for symmetry with Alt+Q and Alt+E, or show the clash state from the Settings card. Ideally both.

Escape always goes somewhere

  • Menu open → close it, focus back on the chevron or chip that opened it.
  • Overlay open → cancel selection, state returns to Idle, panel restores.
  • Countdown running → cancel the capture before it starts.
  • Recording → nothing. Esc must never destroy a recording in progress; Stop is deliberate or it is not a stop.
  • Settings or Gallery → back to the panel.
  • Error showing → dismiss the error, keep the panel.
  • Panel idle → minimise to tray.

What exists in code already: window.rs wires Tab / Shift+Tab through focus_next and focus_prev, every control has a stable accessibility_id, and the status line carries role=Status. Missing: the focus-visible spacer on filled controls, arrow keys in the segmented control, Home / End, every Escape route except the overlay's, and the titlebar buttons — window_button is not focusable(), so stops 10 and 11 are unreachable by keyboard today. The three countdown slots are also three separate stops rather than the one this specifies.
