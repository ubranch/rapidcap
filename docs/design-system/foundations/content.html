Content & voice

A capture tool speaks in five to seven words at a time. Every string in RapidCap is read at a glance, mid-task, by someone who is trying to do something else — so the voice is plain, present tense, and never explains itself.

The rules

  • Sentence case everywhere. Output folder, not Output Folder. Title case is a 1990s toolbar.
  • No terminal punctuation on labels, statuses or errors. A full stop on a four-word label is noise. Ellipsis is allowed and means "still working".
  • Verbs for actions, nouns for things. A button says Stop. A readout says Recording.
  • Never say the obvious noun. 60 FPS in the value means the label is Frame rate, not Video frame rate setting.
  • Never apologise, never blame. No "Sorry", no "You must", no "Please try again".
  • Numbers are facts, not prose. 1280 × 720, 00:42, 12.4 MB — with the multiplication sign, not the letter x.

File names

Today: {process}_{10 random alphanumerics} from OutputNamer, falling back to Screen when the process name is empty. Real output: Screen_9ENJ4BwCIG.png, Telegram_XDdde2nqvu.png, explorer_RtscSVLXL9.png.

Proposal: {process}_{YYYY-MM-DD_HH-mm-ss}.{ext} — Telegram_2026-08-27_14-32-05.png. Same sanitising, same fallback to Screen, one extra field. It sorts chronologically in Explorer with no effort, and "the screenshot I took on Tuesday" becomes findable. Keep a 4-character random suffix only if two captures can land in the same second.

Tooltips

  • Every icon-only control has one. No exceptions.
  • Name the action, then the shortcut: Pause · F9. Not Click to pause the recording.
  • Add state when the icon carries it: System audio is off — click to choose a device.
  • Never repeat a visible label. A chip reading Documents gets the full path as its tooltip, not the word "Documents".
