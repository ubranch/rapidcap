Motion

A capture tool is judged on whether it got out of the way in time. Motion here exists to confirm a press and to soften a colour change — never to introduce a surface, and never on anything the user is timing.

Durations

TokenUsed by
80ms
Press — scale(.985) on cards, chips, buttons
120ms
Hover fill, focus ring, icon colour
160ms
Menu open, saved chip in and out, error bar replacing the footer
240ms
HUD idle fade to 55%, and back on hover
Four values, no more. Anything that seems to need a fifth is either instant or should not move.

Easing

CurveWhere
cubic-bezier(.2, 0, 0, 1)Everything that changes size, position or fill. Fast out of the gate, settles quietly.
linearPure opacity fades — the HUD idle fade and the saved chip expiry. Eased opacity reads as a flicker.

What never animates

SurfaceWhy
Region overlay appearingThe user pressed a hotkey to capture something that is happening now. A 160ms fade is 160ms of the wrong frame.
Region frame and selection rectThey track the cursor. Any easing turns into lag.
HUD moving to a new regionIt jumps. Watching a bar slide across the screen after every re-selection gets old on the second capture.
Timer digits, size badgeNumbers that animate cannot be read at a glance, which is the only reason they exist.
Tray icon stateWindows redraws it on its own schedule; a tween there is a flicker.
Status text swapsCross-fading two strings makes both unreadable for the duration. Swap the text, animate nothing.
Panel showing after tray clickShow it. The click already was the transition.

The one loop

The recording dot pulses, 2s, 1 → .45 → 1. It is the only looping animation in the product, it exists because a static red dot is indistinguishable from a decoration, and it is the difference between "is this recording?" and knowing. It runs in the HUD, the panel status well and the tray icon — the same rhythm in all three, so they read as one signal. Nothing else in RapidCap is allowed to loop.

Reduced motion

  • System reduced-motion on: every duration goes to 0, including the press scale.
  • The recording pulse becomes a static dot at full opacity — the state must still be visible.
  • The HUD idle fade stays, at 0ms: it snaps between 100% and 55%. The point is screen presence, not the transition.

Implementation

GPUI has no CSS transitions. Hover and press fills are style variants applied on state, so they land instantly today — which is acceptable and is what ships now. The three that need real animation are the pulse, the HUD idle fade and the saved chip expiry; each is a cx.spawn loop driving one interpolated value, not a general animation system. Do not build a tween engine for three values.
